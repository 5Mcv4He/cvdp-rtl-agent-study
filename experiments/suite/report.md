# 12 道 RTL 调试题的配对结果

本文保留原三组结果。后续已经补跑 DSH ＋ V4 Pro，四组汇总见 [Agent × 模型对照](factorial-report.md)。

## 实验回答的问题

在固定 ACE-RTL 调试流程时，把 Flash 换成 V4 Pro 会带来什么变化？在固定 Flash 时，把专业流程换成通用的 DeepSeek Harness 会带来什么变化？本次用同一批 CVDP 题目观察首次提交、有限反馈后的结果、调用次数和费用估算。

选择 12 道 `cid016` 任务，涵盖编码、时钟域、算术、控制和缓冲。每题每个配置独立运行两次。分母是预先分配的全部次数，每组 24 次，共 72 次。加法器开发题和先前的五题试跑在本表之外。两次重复来自同一道题，统计时还要保留题目层面的相关性。 [任务与原始 RTL 校准](expanded-design.json) · [逐次结果](expanded-results.json)

## 结果

| 配置 | 首次通过 | 两次模型请求内通过 | 流程结束时通过 | 首次编译并运行 | 观测请求 | 峰时费率估算 | 每次成功的峰时估算 |
|---|---:|---:|---:|---:|---:|---:|---:|
| ACE-RTL ＋ Flash | 7/24 | 7/24 | 12/24 | 23/24 | 71 | $0.107 | $0.0089 |
| ACE-RTL ＋ V4 Pro | 5/24 | 5/24 | 11/24 | 24/24 | 77 | $0.402 | $0.0365 |
| DSH ＋ Flash，关闭工具 | 7/24 | 10/24 | 10/24 | 21/24 | 41 | $0.066 | $0.0066 |

峰时价统一用于估算，便于复算。按实验当天的周日非高峰费率，三组共约 **0.288 美元**。表中所有成功分数都来自用 CVDP 原测试进行的独立重放。并发执行、缓存和两种运行器的计时边界影响耗时，因而未把中位时间用于架构速度排名。 [费率与预算口径](design.json) · [DeepSeek API 费率](https://api-docs.deepseek.com/quick_start/pricing/)

**固定 ACE-RTL 换模型。** 最终结果中 8 对同过，9 对同未过，4 对只有 Flash 通过，3 对只有 Pro 通过。这个样本里 Pro 花费更多，最终通过次数接近。加法器开发题曾出现 Pro 通过而 Flash 失败，逐题选择会改变观察，因此不宜把这组差距当作通用模型排序。

**固定 Flash 换 Agent 配置。** 首次各通过 7 次，其中 6 对同过。按两次观测请求对齐，DSH 通过 10 次，ACE 通过 7 次。ACE 流程结束时通过 12 次，共使用了 71 次请求，其中一次失败反馈后的反思常会消耗两次请求。结论适用于保留角色编排的 ACE 与关闭工具的 DSH 这两种配置，体现的是修复能力和模型调用成本的取舍。

## 读懂通过与失败

| 场景 | 可观察的差异 |
|---|---|
| 64b/66b 编码器 | 六次首次提交均未通过，第二次都通过。五题试跑的两份 ACE 轨迹表明，原候选把复位写成低有效，修复后使用高有效 |
| 多模式计数器、咖啡机、图像行缓冲、Swizzler | 四题在扩展样本的三组两次运行中均无通过。行缓冲出现过编译错误和输出窗口不匹配，咖啡机则有加热信号时序失配 |
| 重复提交 | 在实际提交两版的运行中，ACE＋Flash 有 5/13 次哈希完全相同，ACE＋Pro 为 4/15，DSH＋Flash 为 1/13。多花一次模型调用不会自动带来不同的 RTL |
| 接入错误 | 两道长输入在 DSH 的第一版适配器中被入口长度上限挡住，四次均发生在模型请求前。放宽入口长度后只重跑这四个相同任务配置。原事件及补跑结果记录在结构化结果的 `pre_request_recovery` |

ACE 的八条第二轮生成请求长约 53.9–61.8 kB，超过本地 48,000 字节上限，因而未发送。这些试验在主分析中保留最后一份已评分候选。补充诊断将上限放宽到 64,000 字节，用已保存的角色提示补发原本未发出的八次请求。提取后的八份候选均编译并运行，仍未通过功能测试。这说明放宽该上限在本次重放中补齐了生成和评分，但没有解决这两道题。补发不计入 72 次主实验成绩与费用。DSH 也有第二轮输出达 token 上限或包含多个代码块的轨迹，评分器同样只判定完整交付的候选。 [长度诊断结果](context-limit-results.json) · [补发脚本](../../scripts/probe_context_limit.py)

## 统一了什么

- 三组共享数据、初始 RTL、目标文件、CVDP 原测试和本机 Icarus／cocotb 评分环境。候选通过 `local_import` 独立重放，重新计算实际受测文件哈希。每题的 cocotb 随机种子相同。
- 每次最多两轮。ACE 上限 4 次请求，DSH 最多两次模型回合，关闭工具和自动重试。首次提交与按请求数统计的结果应与各自流程最终结果并读。
- 两边每轮能收到的验证信息限于结果类别。ACE 的角色提示和调试辅助逻辑仍然保留。ACE 显式设置 0.2 和 0.95 的采样参数，DSH 使用 SDK 默认采样设置。SDK 可验证模型、推理模式与使用量事件，实际传输序列化及采样字段仍有差异。
- 结果属于 **同一套测试反馈后重放**。加法器另有独立算术探针，其他任务的模型候选评分仍使用 CVDP 原测试。测试通过说明满足该检查集，测试覆盖和规格一致性需要另外验证。

## 开启工具的 DSH 单题配对（2026-11-22）

此前所有 DSH 成绩都在**关闭工具**的条件下取得：题面和初始 RTL 拼进提示词，模型每次返回整份代码。本次为同一模型（`deepseek-flash`、关闭思考）新增开启工具的配置：模型在独立工作区里拿到题面、初始 RTL 和明确允许的验证命令（`iverilog`/`vvp`），可以用 bash 与文件读取、写入、编辑工具自行检查和修改代码。最终评分不变：每轮结束后由运行器把工作区里指定的候选 RTL 复制出来，走同一条 CVDP `local_import` 独立重放，受测字节逐字节核对。两组的外部反馈相同——每轮提交后只反馈结果类别，最多两轮。[配对结果](tools-pilot.json)

### 隔离与验收

工具能接触文件系统，隔离在真实运行前用**模拟响应**验收（不发任何付费请求）：回环中转层扮演 DeepSeek Messages API，按脚本驱动模型调用真实工具做一组探针。验收覆盖三层：

- **外层 seatbelt**（启动器注入，包住整个 runtime 进程树）：拒绝读取本工作区树和用户主目录（仅放行模型工作区、runtime 二进制和 Icarus Verilog）；拒绝写入上述两个树之外的一切（放行工作区、系统临时区和 `/dev` 的 pty 设备）；拒绝全部网络出站、只放行回环中转端口。
- **凭据**：真实 API key 只存在于中转层；runtime 环境只有占位符 key。工具子进程环境由 DSH 内置的凭据名剔除处理，探针确认其中不含任何 key/token/secret/password 形态的变量（能看到的中转 URL 和 DSH 安装路径记录为非凭据观察项）。
- **运行后扫描**：每次真实运行结束时扫描模型可达的全部文件（工作区 + 中转请求体），断言哨兵金丝雀、真实 key 和其他任务的标记均未出现。

`--probe` 共 12 项断言（工作区可写、逃逸写被拒、哨兵不可读、数据集不可读、外网不可达、Icarus 可用、中转与 SDK 请求计数一致等）；真实运行器在启动前核对验收门，配置任何变更都会使指纹失效并要求重新验收。已知的平台事实也写入验收：runtime 的 SEA 单文件二进制在任何 sandbox-exec 包装下都无法分配 PTY，因此工具组用子进程版 bash 工具；`ps`/`launchctl` 在沙箱内被拒，模型无法读取其他进程的环境。 [验收脚本](../../scripts/run_dsh_tools_study.py)

### 结果

| 条件 | 请求上限 | 实际请求 | 提交 | 判定 | 耗时 | 峰时费用估算 |
|---|---|---:|---:|---|---:|---:|
| DSH＋Flash，关闭工具 | ≤2 次请求 | 1 | 1 | pass | 6.8 s | $0.0017 |
| DSH＋Flash，开启工具 | ≤8 次请求（中转强制） | 7 | 1 | pass | 42 s | $0.0052 |

两个候选修复了**相同的两处语义错误**（第二级 generate 的 `G2/P2` 下标、`sum` 的 `|` 改 `^`），都通过了同一套官方测试。关闭工具组在一次请求里整文件重写（含大量空白调整，规范化后 46 行变更）；工具组用两次 `edit` 精准修改同样的 6 行，没有触碰文件其余部分。请求计数来源不同并已分开记录：关闭工具组来自 SDK 使用量事件，工具组来自中转层的逐请求账本，两者一一吻合。

### 工具有没有帮助：一个具体例子

开启工具的模型在提交前**自己验证了修复**：写了一个 32 位随机向量测试台，用允许的 `iverilog && vvp` 编译运行；第一次输出格式不对，它尝试用 `sed` 修自己的测试台失败（BSD sed 语法），改用 python 修改后看到 `ALL PASS`，随后删除测试产物、复读最终 RTL 才结束。关闭工具的模型同天同题一次请求直接给出正确答案——这道题上工具**没有提高通过率**（题目对模型太容易，存在天花板效应），改变的的是过程证据：提交内容更小、且提交前存在本地验证记录。单题、单次重复的结果不能外推为通过率差异；工具组还额外获得了工作区内自查的全部信息（自写测试台、编译与仿真输出），这是关闭工具组拿不到的。

### 复现

```bash
# 离线隔离验收（模拟响应，不发付费请求；真实运行前必须通过且指纹一致）
.local/dsh-venv/bin/python scripts/run_dsh_tools_study.py --probe

# 真实单题（凭据内联传入，不进 shell 环境；每运行最多 8 次请求，由中转强制）
DEEPSEEK_API_KEY=... .local/dsh-venv/bin/python scripts/run_dsh_tools_study.py \
  --task cvdp_copilot_32_bit_Brent_Kung_PP_adder_0001 --rounds 2 --max-requests 8
```

关闭工具一侧使用既有命令 `scripts/run_dsh_study.py`，历史成绩不变。逐次模型请求与响应、中转账本和探针证据保存在本地运行目录。 [结构化配对结果](tools-pilot.json)

## Linux Compose 校准

在 Ubuntu 24.04 x86_64 上用锁定的官方 Dockerfile 构建镜像，运行 CVDP 自带参考样例及加法器正反对照。LFSR 的三个测试通过，原始加法器复现进位断言，独立行为实现通过。三个结果与 Mac 一致。本校准覆盖这三个控制，12 题配对仍以 macOS 原生重放计分。 [工作流记录](https://github.com/5Mcv4He/cvdp-rtl-agent-study/actions/runs/45004559177) · [机器可读记录](compose-calibration.json)

## 复现

macOS arm64 上从仓库根目录运行：

```bash
bash scripts/setup_study_mac.sh
.local/dsh-venv/bin/python scripts/run_suite.py --confirmed-budget-usd 11 \
  --design experiments/suite/expanded-design.json --workers 3
```

脚本需要本地 `DEEPSEEK_API_KEY`，预算参数用于保守预留额度，实际用量按模型请求和 SDK 事件统计。它将公开任务、每次运行产物与汇总数字分开保存。重跑的模型输出可能不同。评分、任务选择与训练任务的后续推导见 [评测协议](../../docs/protocol.md)、[训练任务方向](../../docs/training-directions.md)。
