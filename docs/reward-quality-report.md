# Reward Quality Report · D2

独立 Verifier 在两道锁定的 RTL 调试题上检出 **9/9** 种定向功能变异，接受 **4/4** 份正确对照，并拒绝两份原始错误 RTL。CVDP 原测试检出 **6/9** 种变异，也接受全部正确对照、拒绝两份原始 RTL。15 份实现共完成 105 次离线评分，模型调用为 0，V1 历史分数保持原样。 [可运行 Verifier](../scripts/verify_rtl_d2.py) · [数据和逐项计数](../experiments/v2/d2-results.json)

独立检查依据锁定的 CVDP 题面和随题给出的模块接口及 RTL 注释。检查器用 Python 生成规格期望值，Icarus 运行被测实现，仿真 testbench 比较实际值与期望值。原测试通过项目既有 CVDP 本机入口单独重放。下面的 64b/66b 行为只对应此题所定义的同步头、负载和时序。 [数据版本锁](../experiments/P0/lock.json) · [NVIDIA 数据集](https://huggingface.co/datasets/nvidia/cvdp-benchmark-dataset) · [CVDP 原评测](https://github.com/NVlabs/cvdp_benchmark)

## 规格与检查项

| 任务 | 规格及来源 | 独立检查 |
|---|---|---|
| Brent–Kung | 公共题面给出 32 位二进制加法、输入进位和输出进位的示例。对已知二进制输入，33 位结果为 a + b + carry_in | 以 Python 整数加法作 oracle，分别核对低 32 位与最高进位位；每组随机操作数检查两种输入进位 |
| Brent–Kung | 全宽溢出、零、最高位和贯穿不同位置的进位应正确 | 98 次边界组合、128 次定向进位链、8,192 次随机操作数及进位组合。每个种子共 8,418 次观测，包含重复输入 |
| Brent–Kung | 保持原端口名称与位宽。题面将模块描述为 Brent–Kung 加法器 | testbench 用命名端口连接并检查位宽。结构型正对照实现前缀树，行为型正对照用于验证功能判分与实现结构无关。电路拓扑、综合后面积和时序未评分 |
| 64b/66b | 非复位时，控制字为 0 时输出数据和同步头 01，控制字非零时输出清零负载和同步头 10 | 穷举 256 个控制字。每次先写非零负载，观察切到控制模式能否清除旧值；头和负载分开比较 |
| 64b/66b | 题面规定高有效复位，随题接口注释规定异步；复位期间整个输出为 0 | 先写已知非零值，再分别在时钟低、高电平断言复位。检查时钟上升沿遇到复位时的优先级 |
| 64b/66b | 随题公开 RTL 使用上升沿更新。保持该时序契约，解除复位和改输入不会自行更新输出 | 在上升沿、下降沿及输入变化后观测，检查复位解除保持、两沿之间保持和复位后首拍；再补 128 个随机数据或控制周期。每个种子共 1,293 个观测点 |
| 64b/66b | 保持原端口名称与位宽 | 命名连接及位宽检查。头和负载用四态不等比较，规格应为确定值时 X/Z 计作失配 |

本轮两套 oracle 都从模块对外行为出发。加法器 oracle 不读取内部前缀信号，编码器 oracle 用独立时钟事件驱动的状态描述。本轮输入限于数字仿真中明确的二进制值；未规定上电前状态、X/Z 输入语义、物理时序或完整通信协议。

## 测量结果

每道题各两份独立编写的正对照。加法器分别使用直接扩位加法和独立的上扫/下扫前缀树，编码器分别使用单个 66 位寄存器和分离的同步头、负载寄存器。同一份原始错误实现直接从锁定行的输入上下文取得。定向变异从对应的主正对照出发，每次改变一个行为；所有变异均完成编译并由独立测试的功能反例证实非等价。

| 任务、实现 | 独立 Verifier | CVDP 原测试 |
|---|---|---|
| 加法器 · 两种正确实现 | 2/2 通过 | 2/2 通过 |
| 加法器 · 原始错误实现 | 功能失败 | 功能失败 |
| 加法器 · 忽略输入进位 | 功能失败 | 功能失败 |
| 加法器 · 输出进位固定为 0 | 功能失败 | 功能失败 |
| 加法器 · 丢弃操作数 A 的第 17 位（从 0 数） | 功能失败 | 功能失败 |
| 加法器 · 两操作数逐位互补时丢失输入进位 | 功能失败 | **通过，漏检** |
| 编码器 · 两种正确实现 | 2/2 通过 | 2/2 通过 |
| 编码器 · 原始错误实现 | 功能失败 | 功能失败 |
| 编码器 · 控制模式保留旧负载 | 功能失败 | 功能失败 |
| 编码器 · 控制模式写入错误同步头 | 功能失败 | 功能失败 |
| 编码器 · 仅在时钟上升沿响应复位 | 功能失败 | **通过，漏检** |
| 编码器 · 只将 FF 识别为控制模式 | 功能失败 | 功能失败 |
| 编码器 · 在下降沿采样 | 功能失败 | **通过，漏检** |

加法器漏检的反例可用 a=0、b=0xFFFFFFFF、carry_in=1 表示。正确结果的低 32 位为 0，carry_out 为 1。变异返回 0xFFFFFFFF 和 0。此前静态审计发现，这道题的 10 组随机输入未运行断言。本轮给出了一个实际通过原测试的错误实现。 [上游测试静态审计](../experiments/P0/check_first_task.py)

编码器的同步复位变异在时钟不变时无法清除已知非零输出。在下降沿采样的变异会提前更新或错过约定的上升沿。在两类变异上，原测试均通过 10 项，独立检查在明确的异步复位或边沿约束处失败。这是所测实现的实证漏检，无法由此推导原测试对全部潜在时序错误的检出率。

稳定性方面，每个实现用固定种子 20261122 在两套评分器分别重放三次，共 90 次。独立评分的判定、分组计数和首个失败位置复现，CVDP 的判定与测试总数复现。再换种子 20261123 跑 15 次独立评分，15 份实现的判定相同。两个种子均公开，仅用于可复现性与敏感性检查。假拒绝观测为 0/4，独立变异漏检为 0/9，这些是本组定向对照的计数。

## 终局奖励判断

**可以作为这两题的离线功能验收信号。接入 Agent 强化学习作为唯一终局奖励的条件还未满足。**

在当前受信离线环境里，已提交候选在规定接口下通过全部独立检查，可以记功能分 1；出现可重放的规格反例，可以记 0。编译或接口失败先保留阶段类别，确认由候选导致且在已承诺的工具链范围内，再按交付契约决定是否记 0。环境故障、超时及未跑完整的检查先保留无有效分数状态。测试程序要求全部预定观测点和完整结束标记，即使出现部分正确输出也不授予通过。

正式训练接入仍有三个待验证条件：

- **把终评从求解侧隔离。** 这版公开开发 Verifier 使用同一仿真进程中的 testbench 与结果标记，面向已审查的固定样本。部署时需要把实际提交、受信评分器、测试种子与求解工具的权限隔开，检查终评分数是否确由评分器产生，并用独立冻结的检查覆盖未见输入。
- **把奖励声明限制在实测规格内。** 加法器输入空间远大于仿真样本；若要求所有输入正确，可优先做 33 位算术等价验证。若还要求保留 Brent–Kung 拓扑，需另建结构检查。编码器应继续覆盖复位边沿和状态转移；目前的结果不外推到完整协议或物理实现。
- **用独立来源检验覆盖与误拒。** 还需要更多合规实现、独立设计的反例与保留任务族。训练数据和最终评测任务应隔离。这两道已公开题可用于开发 Verifier 和诊断，不能当作训练后的独立效果证明。

## 运行

对已经审查的候选，可以使用仓库本机 Icarus 或 PATH 中的 Icarus 运行公开开发检查：

```bash
python3 scripts/verify_rtl_d2.py adder /path/to/candidate.sv
python3 scripts/verify_rtl_d2.py encoder /path/to/candidate.sv
```

复做完整变异对照需要既有的锁定 CVDP 本机环境以及四份正对照。项目本地保存在 .local/d2-controls，可用 --controls 指向对应目录。原 RTL 从锁定数据集中读取，变异规则在执行脚本内。四份正对照的哈希、每条路径的判定与分组计数在公开 JSON 中。正对照 RTL、本机工作日志和原 CVDP 验收源码留在私有工作区。

```bash
python3 scripts/run_reward_quality_d2.py
```

本次通过的代码路径为 macOS arm64 上的 Icarus 13.0 和既有 CVDP 本机 runner。整个 D2 使用固定代码，并为每次评分创建独立工作目录。 [变异与重放执行脚本](../scripts/run_reward_quality_d2.py)
