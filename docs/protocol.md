# 对照协议草案 v0.1
**实验单位。** 一个任务 × 一个配置 × 一个独立 session × 一次预先分配的重复。先对同一批约 5 个预选任务做连通性试验，固定 ID、分层依据和顺序，再运行各组。首题调试用过的轨迹标为开发集。正式测量使用另行冻结的任务清单，公开训练污染无法排除。记录工具、日期、provider 和实际响应的模型名；浮动别名无法保证后端权重一致时，交错运行配对、记录时间并降低结论强度。小样本报告逐题配对结果与分子/分母。

| 条件 | 实验一 | 实验二 |
|---|---|---|
| 变化项 | ACE 三角色同时换模型，含内部/重试调用；仅观察整套系统在不同模型下的差异 | ACE 与 DSH，固定相同服务、模型、可支持的推理模式和参数 |
| 固定项 | 题目字节、目标文件、ACE 路由以外的代码、工具与反馈、验收镜像、预先指定预算 | 同一行、公开材料、可见验证信息、最终导入格式、设备、测试与预算。保留各自角色提示和编排 |
| 资源口径 | 优先报告相同总 token 及时间上限下的通过率，另列按费用对齐和本机原生配置的结果 | 同左。首次提交为附加读数，分别记录首个完整候选和达到首个 PASS 的累计资源 |

**反馈条件。** 主对照拟选择“相同可见反馈下解决任务”。每次提交只返回双方约定的同一诊断范围（编译状态、失败阶段、裁剪后的用例差异），记录交到每个角色的实际内容与次数。两方复用同一反馈服务或在相同执行环境做一致性校准。ACE 现有额外 checker/文件上下文按角色及分支审计；无法限制或对称提供时只报告原生系统比较，标明信息差。官方同题测试若已用于求解，终评命名为“同套测试重放”。如研究泛化，另设“只给编译/自写测试，官方验收仅最后一次可见”的条件，或独立保留规范驱动测试；记录对 ACE 反馈逻辑的改动，审批后另报告，不覆盖官方得分。

**资源控制。** 配对任务运行于同一 runner，串行、同样的超时、并行尝试数和重试策略。锁定可用模型参数、最大单次输出、总输入+输出预算、任务时间、请求和评分调用上限，含 Coordinator 和重试。推理 token 若已计入输出，避免重复累加；未返回字段记 null。记录终止前最后一个完整候选及超额情况。先测一次确定可行上限，再冻结批次。多次独立重复使用新目录/进程/session，支持则设模型 seed，另记仿真 seed、缓存命中、网络等待。缓存、一轮多请求、并行早停与不同 tokenizer 意味着相同轮数并不提供相同资源；公布原生配置与限额配置的各自结果。

**可信执行。** 控制器持有完整 JSONL、测试、参考、凭据和独立判分区。求解者只获 input 及目标路径，收集指定文件；禁止联网查答案。DSH shell 需要受限挂载及环境，提供模型接口的受信进程与执行命令的工作区分离；验证时尝试读取已知哨兵文件并断言失败。公开源文件路径和服务错误也可能泄漏 checker。固定候选哈希，验收在新目录重建，禁止继承上轮产物。核对测试、harness 哈希、实际断言和执行数量。发现评分缺陷时保存官方 verdict 和独立复核标志，不编辑原测试、不追溯改分。

**应保留的记录。** 每次运行保存 manifest（commit、数据哈希、模型/服务/实际请求参数、工具与镜像、任务/角色/重复 ID、预算、seed、输入文件哈希）、公开材料、按时间排序的事件和原始产物。每次真实请求关联请求 ID、发送的系统及用户消息/工具定义和可获得的外显响应、usage/finish_reason、等待与重试；只留必要字段，去掉认证头及密钥。每次工具执行记命令、输入输出、退出码、耗时；保存每版 RTL、diff、编译与仿真原始日志、Verifier 报告、DSH session 和 ACE 角色轨迹。原始数据私有，外部报告引用脱敏副本。日志缺失标 unknown；SDK 事件不一定涵盖模型 HTTP 请求，应对账。

**统计与归因。** Task pass = 有效运行中最终通过数/有效运行数；另报计划运行数、有效数及按所有分配运行统计的端到端成功率，公开基础设施/API 错误和重跑。分别报分类内通过率、宏/微平均、首个候选编译成功率与首轮/最终通过率，编译不明单列。记录每题预算消耗、模型/工具/验收调用数、墙钟、首个成功时间、输入/输出/缓存/推理 token；成本按运行日供应商计费口径计算并保留单价版本，cost per success 用全部计费成本/成功数（零成功时未定义）。多次重复按任务配对，保留组间胜负、同过/同败、分布和不确定性，不用五题推断稳定排名。

按轨迹标注首个阻断点及可能原因，例如 RTL 算术/协议错误、生成不完整、Agent 提取/调度问题、工具链故障、API 限流/截断、预算耗尽或评分疑点。区分编译失败、合法失败、超时和未执行。模型与架构的因果归因限定在已控制的条件内。先检查首个成功、首个失败及任何两系统判定不一致的完整轨迹。
