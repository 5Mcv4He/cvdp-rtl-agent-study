# 从 RTL 调试轨迹设计训练任务

这项研究记录了候选代码、编译、仿真断言和独立重放。根据这些证据，可以先设计三类可检验的训练信号。

| 实测现象 | 可以构造的任务 | 验收设计 |
|---|---|---|
| Brent–Kung 加法器的进位树在大范围输入上算错。Flash 的第二份候选哈希与第一份相同 | 给出有错的分层归并网络和明确的 33 位接口行为，要求定位错误索引并提交可编译 RTL | 同时检查低 32 位与进位。固定若干进位链边界和独立随机输入。检查实际断言数。记录候选哈希与调用次数 |
| 64b/66b 编码器首轮使用错误的复位极性。两种 ACE 模型第二轮改为高有效后通过原测试 | 在同时涉及复位、数据和控制模式的设计中，按公开规范维护时序约束 | 分别覆盖复位触发、解除后首个周期、模式切换。以复位前写入非零状态作为对照 |
| 计数器题的 DSH 回复含有效代码和解释，但提取器报错 | 在文件交付型任务中同时记录模型输出、解析过程与实际受测文件 | 将交付失败和 RTL 功能错误分别记账。解析后验证唯一目标文件和哈希，再让原测试判分 |

优先建设彼此独立的三段反馈。一段用于快速告知编译或功能失败，一段由隔离的最终测试验收，一段用于分析失败原因。求解侧能看到的信息应固定并记录。这样可以区分模型学会了约束定位、依赖提供的样例，还是只适应了某个测试脚本。

用于训练的评分可以把编译和提交完整性作为过程指标，最终分数依赖有效覆盖缺陷的测试。先验证缺陷版本会失败、参考行为会通过，再用保留版本的代表性错误实现检查测试是否容易放行。资源效率应单独计量，尤其要记录同一候选重复提交和反思角色的额外请求。

这些是由实验导出的待检验方案。独立算术探针只对加法器做了扩展检查，其他配对任务的分数仍来自 CVDP 原测试。 [加法器试验](../experiments/P2/log.md) · [五题案例](../experiments/suite/pilot.md) · [评测协议](protocol.md)
